# 맵 만들기

맵은 「무엇이 언제 로드되는가」를 파일에서 읽어 낸 것입니다. 세션을 돌리지 않아도 나오므로 다른 스킬보다 먼저 돌립니다.

## 차례

1. 저장소 루트에서 맵을 만듭니다.

   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/scan.mjs" --root .
   ```

2. 보고서를 조립합니다. 절차는 `report` 스킬에 있습니다.
3. 사용자에게는 보고서 파일의 경로와, 맵에서 가장 먼저 볼 것 세 가지만 말합니다. 나머지는 보고서가 보여 줍니다.

## 맵이 답하는 물음

| 물음 | 보고서의 어디 |
|---|---|
| 이 지시문은 언제 로드되나 | 「맵」에서 노드를 누르면 상세 패널의 「언제 로드되나」 |
| 이 소스 파일을 열면 무엇이 로드되나 | 「파일」에 경로를 적는다 |
| 항상 로드되는 내용은 무엇이 차지하나 | 「제안」의 맨 위 막대 |
| 잘리거나 끊긴 것이 있나 | 「제안」의 「잘리는 내용」 · 「깨진 참조」 |

## 강제 수준 다섯

맵은 모든 지시문에 수준을 하나 붙입니다. 1 · 2 · 3 은 자동으로 로드되고, 4 · 5 는 모델이 골라야 로드됩니다.

| 수준 | 의미 | 예 |
|---|---|---|
| 1 항상 로드 | 세션이 시작되면 로드된다 | 루트 CLAUDE.md, 스킬의 이름과 설명 |
| 2 조건부 로드 | 맞는 파일을 Read · Edit · Write 로 열면 로드된다 | 폴더의 CLAUDE.md, `paths` 가 있는 규칙 |
| 3 훅이 강제 | 이벤트가 발생하면 자동으로 실행된다 | settings.json 의 훅 |
| 4 지시문이 참조 | 지시문이 이름을 언급해서 모델이 따를 이유가 있다 | CLAUDE.md 가 언급하는 스킬 |
| 5 모델이 고름 | 모델이 설명만 보고 정한다 | 아무 지시문도 언급하지 않는 스킬 |

지시문은 위치 넷으로 나눠 적습니다(`source`). 수준이 같아도 로드 단위가 달라서 따로 봅니다.

| 위치 | 수준 | 로드 단위 |
|---|---|---|
| 루트 지시문(`root`) | 1 | 세션마다 파일 전체 |
| 항상 로드되는 규칙(`rule-always`) | 1 | `paths` 가 없어 루트와 같다 |
| 폴더 지시문(`folder`) | 2 | 그 폴더의 어느 파일을 열어도 파일 전체 |
| 경로 규칙(`rule-paths`) | 2 | 경로 패턴에 맞는 파일을 열 때만 파일 전체 |

폴더 지시문은 섹션마다 참조하는 경로를 보고, 폴더의 한 곳만 다루는 섹션을 「범위가 좁은 섹션」(`narrow`)으로 표시합니다. 경로 규칙으로 옮길 후보입니다.

## 읽을 때 조심할 것

- 수준 2 의 내용은 길이 상한이 있습니다. 컨텍스트 20만 세션은 4만 자에서, 100만 세션은 15만 자에서 뒤가 잘립니다. 경고는 뜨지 않습니다.
- 수준 2 의 내용은 로드될 때 대화의 뒤에 붙습니다. 앞쪽에 캐시된 부분을 바꾸지 않으므로, 항상 로드되는 내용을 수준 2 로 옮기면 모든 요청의 앞쪽이 줄어듭니다.
- 맵은 「로드될 수 있는 경로」이지 「실제로 로드된 것」이 아닙니다. 4 · 5 가 실제로 얼마나 로드되는지는 `trace` 와 `test` 스킬로 측정합니다.
- 맵의 제안 가운데 「측정값」만 그대로 믿습니다. 「추정」과 「테스트 필요」는 `advise` 스킬의 절차로 확인하고 나서 권합니다.
