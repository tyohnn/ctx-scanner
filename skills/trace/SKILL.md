# 세션 기록 읽기

이 플러그인이 켜져 있는 동안 훅이 사건을 한 줄씩 적습니다. 적는 것은 이름 · 경로 · 크기 · 때뿐이고, 파일의 내용과 도구의 입력 · 출력은 적지 않습니다.

## 차례

1. 지도가 없으면 `map` 스킬로 먼저 만듭니다. 기록은 지도에 이어야 읽힙니다.
2. 보고서를 조립합니다(`report` 스킬). 기록이 있으면 「기록」 화면이 생깁니다.
3. 「기록」 화면의 위쪽 알림과 폭포를 읽고 아래 물음에 답합니다.

## 기록에서 볼 것

| 물음 | 보는 법 |
|---|---|
| 규약이 언제 실렸나 | 종류가 「지시문」인 줄의 때와 까닭. 「일으킨 것」이 그 글을 불러온 파일이다 |
| 규약 없이 일한 구간이 있나 | 첫 「폴더 진입」 · 「경로 일치」 줄보다 앞에 있는 도구 줄 |
| 스킬을 불렀나 | 종류가 「스킬」인 줄. 없으면 설명만 실리고 본문은 읽히지 않은 것이다 |
| 한 번에 얼마나 실렸나 | 위쪽 띠의 계단. 계단이 높이 뛰는 자리가 큰 글이 실린 때다 |

## 알아 둘 것

- ⚠ **Bash 의 `cat` · `grep` 으로 파일을 읽으면 폴더 지시문과 경로 규칙이 실리지 않습니다.** 싣는 것은 Read · Edit · Write 뿐입니다. 기록에서 지시문이 늦게 실렸다면 그 앞의 도구가 Bash 였는지부터 봅니다.
- 스킬과 MCP 에는 「실렸다」는 사건이 따로 없습니다. 스킬은 Skill 도구를 부른 줄로 알아봅니다.
- 압축 뒤에는 폴더 지시문과 경로 규칙이 돌아오지 않습니다. 그 폴더의 파일을 다시 열어야 실립니다.
- 프롬프트는 길이만 적습니다. 앞 120자를 함께 적으려면 `CTXSCOPE_PROMPT_PREVIEW=1` 을 줍니다.
- 한 세션의 기록은 한 번 일어난 일입니다. 「늘 그렇다」고 말하려면 `test` 스킬로 여러 번 돌립니다.
