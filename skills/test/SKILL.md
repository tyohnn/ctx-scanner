# 시나리오를 짜고 돌리기

수준 4 · 5 의 글은 모델이 골라야 실리므로 「실린다 · 안 실린다」가 아니라 비율로만 말할 수 있습니다. 이 스킬은 그 비율을 재는 시험을 짜는 법입니다. 시험을 잘못 짜면 숫자는 나오지만 아무것도 말해 주지 않습니다.

## 시험을 짜는 규칙 일곱

1. **가설을 한 문장으로 적습니다.** 「화면의 글을 고쳐 달라는 요청을 받으면 ux-writing 스킬의 본문을 읽는다」처럼 요청과 실려야 할 것을 함께 적습니다. 한 시나리오에 가설은 하나입니다.
2. **요청은 실제 사용자의 말투로 씁니다.** 스킬 이름이나 파일 경로를 요청에 넣지 않습니다. 같은 뜻의 다른 문장을 셋 만들어 돌려 씁니다.
3. **세션에 가설을 알려 주지 않습니다.** 건네는 것은 요청 문장뿐입니다. 「스킬을 쓰는지 볼 거야」라고 말하면 모델은 그 답을 맞히러 갑니다.
4. **판정은 기록만 봅니다.** 세션이 「읽었습니다」라고 말한 것은 증거가 아닙니다. 훅이 적은 줄에 있어야 실린 것입니다.
5. **대조 시나리오를 함께 둡니다.** 무관한 요청에서는 실리지 않는지를 같이 재야 「늘 불리는 스킬」과 「맞을 때 불리는 스킬」이 갈립니다.
6. **횟수와 함께 말합니다.** 기본은 다섯 번이고 「5번 가운데 4번」으로 적습니다. 백분율로 바꿔 말하지 않습니다.
7. **한 번에 하나만 바꿉니다.** 지시문을 고쳐 다시 잴 때는 한 군데만 고칩니다. 문장 셋 가운데 하나는 고치는 동안 보지 않고 남겨 두었다가 마지막에만 돌립니다.

## 시나리오 파일

```json
{
    "scenarios": [
        {
            "id": "copy-skill", "runs": 5,
            "hypothesis": "화면의 글을 고쳐 달라는 요청을 받으면 ux-writing 스킬의 본문을 읽는다",
            "variants": ["로그인 화면 안내 문구가 딱딱한데 다듬어 줘", "권한 없을 때 뜨는 화면 글 좀 손봐 줘", "이 화면 글이 어색해. 자연스럽게 고쳐 줘"],
            "expect": { "skills": ["ux-writing"] }
        },
        {
            "id": "copy-rule", "sameRunsAs": "copy-skill",
            "hypothesis": "같은 요청에서 화면 규약이 실린다",
            "expect": { "loads": [".claude/rules/screens.md"] }
        },
        {
            "id": "control", "runs": 3, "control": true,
            "hypothesis": "화면과 무관한 요청에서는 ux-writing 을 읽지 않는다",
            "variants": ["legal.task 에 메모 컬럼을 추가하는 마이그레이션 써 줘"],
            "expect": { "notSkills": ["ux-writing"] }
        }
    ]
}
```

`expect` 에는 `skills` · `loads`(실려야 함)와 `notSkills` · `notLoads`(실리면 안 됨)를 적습니다. `sameRunsAs` 를 적으면 세션을 새로 돌리지 않고 다른 시나리오의 세션으로 판정합니다. 같은 세션에서 가설을 여럿 잴 때 씁니다.

## 돌리기

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/run-scenario.mjs" --scenarios <시나리오 파일> --root .
```

- 세션마다 작업 폴더를 따로 떼어(git worktree) 돌리고 끝나면 지웁니다. 세션이 고친 파일은 저장소에 남지 않습니다.
- ⚠ 한 번 돌리는 데 한 세션만큼의 토큰이 듭니다. 돌리기 전에 「시나리오 몇 개, 세션 몇 번」인지 사용자에게 한 줄로 알립니다.
- 끝나면 `report` 스킬로 보고서를 조립합니다. 「시나리오」 화면이 생기고, 줄을 누르면 그 세션의 기록이 열립니다.

## 「늘 실리는 곳에서 빼도 되나」를 재는 법

1. 그 절이 지켜 주는 행동을 가설로 적고 지금 상태에서 다섯 번 돌립니다.
2. 절을 뺀(또는 경로 규칙으로 내린) 가지에서 같은 시나리오를 다섯 번 돌립니다.
3. 결과가 같으면 내립니다. 달라지면 그 절은 늘 실리는 값을 하는 것이므로 둡니다.

결과를 `advise` 스킬에 넘겨 제안의 「재 봐야 함」을 「잰 사실」로 바꿉니다.
