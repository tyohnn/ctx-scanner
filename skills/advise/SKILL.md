# 개선 제안

스크립트는 측정할 수 있는 것만 제안합니다. 내용을 읽어야 판단되는 것은 이 스킬이 맡습니다. 판단한 것은 `advice.json` 에 적어 보고서에 함께 넣습니다.

## 차례

1. 맵과 보고서가 없으면 `map` · `report` 스킬로 만듭니다.
2. 스크립트가 낸 제안을 읽고, 아래 「평가하는 법」으로 하나씩 확인합니다.
3. 판단을 자료 폴더의 `advice.json` 에 적고 보고서를 다시 조립합니다.
4. 사용자에게는 `report` 스킬의 「건넬 때」 세 가지(항상 로드되는 자수 · 먼저 할 것 · 테스트해야 알 것)와 보고서 경로를 말합니다. ⚠ 지시문을 직접 고치지 않습니다. 고치는 일은 사용자가 고른 뒤입니다.

## 평가하는 법

**항상 로드되는 것(수준 1)은 자격을 따집니다.** 루트 CLAUDE.md 의 섹션과 스킬 설명 하나하나에 세 가지를 묻습니다.

| 물음 | 옮기는 쪽 | 두는 쪽 |
|---|---|---|
| 범위: 어떤 작업에 필요한가 | 특정 폴더 · 파일 종류에서만 필요하다 | 어느 작업에서나 필요하다 |
| 빼 보기: 빼면 행동이 달라지나 | 시나리오 결과가 같다 | 결과가 나빠진다 |
| 피해: 어길 때 무엇을 잃나 | 고치면 되는 것 | 되돌리기 어려운 것(보안 · 스키마 · 밖으로 나가는 것) |

옮길 곳은 `references/placement.md` 의 「고르는 차례」로 정하고 루트에는 참조하는 한 줄만 남깁니다.

**조건이 맞을 때 로드되는 것(수준 2)은 위치가 맞는지 봅니다.** 폴더 CLAUDE.md 와 `paths` 있는 규칙은 로드되는 시점은 같고 로드 단위가 다릅니다. 폴더 지시문은 그 폴더의 어느 파일을 열어도 전부 로드되고, 경로 규칙은 경로에 맞는 파일을 열 때만 로드됩니다. 스크립트는 위치가 어긋난 신호 넷을 `placement` 제안으로 냅니다.

| 제안 id | 측정한 것 | 읽고 정할 것 |
|---|---|---|
| `split:` | 폴더 지시문의 섹션이 참조하는 경로가 폴더의 한 곳에 모여 있다(`_components/` · `lib/` 처럼 함께 쓰는 구현의 자리는 세지 않는다) | 섹션의 내용이 정말 그곳에만 걸리는지. 경로는 예로 든 것일 뿐이고 규약은 폴더 전체에 걸릴 수 있다 |
| `dup:` | 여러 지시문에 줄의 절반 이상이 같은 섹션이 있다 | 묶을 경로와, 폴더마다 남길 차이 |
| `same-topic:` | 제목이 같고 낱말이 20% 넘게 겹치는 섹션이 여러 폴더에 있다 | 같은 규약의 사본인지, 폴더마다 다른 내용인지(명령어 · 환경 변수는 대개 다르다) |
| `broad:` · `always-rule:` | 규칙의 조건이 넓거나 없어서 거의 항상 로드된다 | 루트로 옮길 내용인지, 경로를 좁힐 내용인지 |

항상 로드되는 것을 줄이는 `demote` 제안도 셋입니다. `demote:` 는 루트의 섹션이 이미 있는 규칙의 범위 안에 있다는 측정이고, `ablate:` 는 루트의 20% 넘게 차지하는 섹션을 빼고 시나리오를 돌려 보라는 것이며, `free-skills` 는 어느 지시문도 (스킬을 거쳐서도) 가리키지 않는 스킬의 설명입니다.

기록에 「열지 않은 곳의 섹션이 함께 로드됐습니다」가 있으면 `split:` 제안의 근거로 덧붙입니다. 실제 세션에서 불필요하게 로드된 글자 수입니다.

섹션 하나를 어디로 보낼지는 `references/placement.md` 를 읽고 정합니다. 반대 방향도 봅니다. 폴더 하나의 거의 모든 파일에 맞는 규칙은 그 폴더의 CLAUDE.md 에 있는 편이 찾기 쉽습니다.

**저장소 전체는 겹침과 빈칸으로 봅니다.** 보고서의 「플로우」는 개발 영역(서버 액션 · 유스케이스 · 화면 …)과 위치(앱 · 패키지)마다 파일을 건드릴 때 로드되는 것을 세 축으로 나눠 보여 줍니다. 폴더(폴더 CLAUDE.md) · 계층(계층 규약 규칙) · 도메인(도메인 용어 규칙)이고, 그 뒤에 지시문이 가리키는 스킬이 이어집니다. 스크립트는 축 사이의 겹침과 빈칸을 `mece` 제안으로 냅니다. 빈칸 칸의 목록은 `map.json` 의 `gaps`(`layer` · `domain`, 파일이 많은 칸부터)에 있으니 화면을 열지 않고 그것을 읽습니다.

| 볼 것 | 제안 id | 기준 |
|---|---|---|
| 같은 말이 두 곳에 있나 | `term-dup:` · `rule-overlap:` · `dup:` | 한 곳에만 두고 다른 곳은 지우거나 한 줄로 가리킨다 |
| 내용이 맞는 축에 있나 | `terms-home:` · `defer:` · `long-rule:` | 용어는 도메인 용어 규칙, 여러 앱 공통 규약은 계층 규칙, 절차는 스킬 |
| 비어 있는 칸이 있나 | `gap:` · `no-layer:` · `no-glossary` | 그 영역에 공통 규약이 실제로 있을 때만 채운다 |
| 스킬로 넘어가는 길이 있나 | `pointed-skills` · `hidden-skill:` · `unindexed:` | 규칙의 마지막 줄이 조건과 경로로 스킬을 가리키고, 그 스킬은 목록에서 뺀다 |

규칙을 계층 규약과 도메인 용어로 나누는 법, 규칙에서 스킬로 넘기는 한 줄, `skillOverrides`, CLAUDE.md 세 층(루트 · 앱 색인 · 기능 폴더)의 기준과 템플릿은 `references/layout.md` 에 있습니다. 규칙을 새로 나누거나 여러 지시문을 한꺼번에 옮기는 제안을 쓸 때는 먼저 읽습니다.

**모델이 골라야 로드되는 것(수준 4 · 5)은 필수인지 선택인지 정합니다.** 꼭 읽혀야 하는 것이면 「필수」, 아니면 「선택」입니다. 필수인데 수준 5 에 있으면 수준을 높입니다. 방법은 셋입니다: 그 작업의 경로 규칙에서 이름을 언급하거나(4), 내용을 경로 규칙으로 옮기거나(2), 훅으로 강제합니다(3). 선택인데 한 번도 호출되지 않은 스킬은 설명만 공간을 차지하므로 목록에서 빼거나 지웁니다.

**문장 하나하나는 정본이 어디인지로 봅니다.** 지시문에는 코드를 읽어서는 알 수 없는 것만 둡니다. 문장마다 두 가지를 묻습니다: 코드나 결정 문서를 읽으면 알 수 있나, 그리고 클로드가 그것을 찾아 읽겠나. 앞의 답이 「예」인 문장은 사본이고, 화면이나 코드가 바뀌면 그대로 남아 정본과 갈라집니다. 스크립트는 루트 · 폴더 지시문 · 경로 규칙의 문장을 일곱 종류로 가르고(`map.json` 노드의 `content`), 1,500자 넘는 지시문에서 상태 기술과 결정 경위가 30% 이상이면 `content` 제안(`derivable:`)을 냅니다.

| 종류 | 예 | 둘 곳 |
|---|---|---|
| 금지와 함정 | 「되돌리지 않습니다」 · ⚠ 로 시작하는 줄 | 지시문. 이것이 지시문의 몫입니다 |
| 명령 | `npm run …` 같이 짐작할 수 없는 명령 | 지시문 |
| 절차 | 번호가 붙은 여러 단계 | 스킬 |
| 용어 | 「쓰지 않는 말」 칸이 있는 표 | 도메인 용어 규칙 |
| 상태 기술 | 「서랍은 정보 · 거래 탭으로 열립니다」 · 주소 값 | 지웁니다. 코드가 정본입니다 |
| 결정 경위 | 「종전에는 … 였습니다」 | 결정 문서. 지시문에는 「~하지 않는다」 한 줄 제약과 문서 경로만 남깁니다 |

판별은 낱말로 하므로 `heuristic` 입니다. 「사용자 결정」 표시가 붙은 문장은 제약으로 셉니다. 사람이 정한 것은 코드를 읽어도 왜 그런지 알 수 없어서입니다.

**잘리는 내용과 깨진 참조는 그대로 고칩니다.** 측정값이라 따로 확인할 것이 없습니다.

## advice.json

```json
{
    "suggestions": [
        {
            "id": "demote:커밋", "kind": "demote", "severity": "medium", "confidence": "heuristic",
            "title": "루트의 「커밋」 섹션은 커밋할 때만 필요합니다",
            "evidence": "커밋 메시지의 형식만 다루고, 코드를 읽거나 고치는 동안에는 쓰이지 않습니다.",
            "action": "섹션을 스킬로 옮기고 루트에는 「커밋 전에 그 스킬을 읽는다」 한 줄만 남깁니다.",
            "targets": ["CLAUDE.md"], "saves": 487
        }
    ]
}
```

- `id` 가 스크립트의 제안과 같으면 그 제안을 덮어씁니다. 시나리오로 확인했으면 `confidence` 를 `measured` 로 바꾸고 `evidence` 에 「5번 가운데 몇 번」을 적습니다.
- `kind` 는 `demote`(항상 로드되는 내용 줄이기) · `placement`(폴더 지시문 · 규칙 · 스킬 사이에서 위치 변경) · `mece`(겹침과 빈칸) · `content`(코드가 정본인 문장) · `truncation` · `dead-ref` · `coverage` · `trace` 가운데 하나입니다.
- 위치를 옮기는 제안의 `action` 에는 옮길 곳을 그대로 쓸 수 있게 적습니다. 규칙이면 파일 이름과 `paths` 값, 폴더 지시문이면 경로, 스킬이면 이름입니다.
- `confidence` 를 속이지 않습니다. 내용만 읽고 내린 판단은 `heuristic` 입니다.
- 스크립트의 제안을 평가했으면 `verdict` 에 적습니다. `accept`(받아들임) · `modify`(고쳐서 받아들임, `action` 을 고친 대로 씁니다) · `keep`(그대로 둠, 일부러 다르게 둔 곳) · `false-positive`(거짓 신호, 스크립트가 잘못 잰 것) 가운데 하나입니다. 보고서가 배지로 보여 주고 `keep` · `false-positive` 는 아래로 내립니다. 제목을 바꿔 판정을 표시하지 않습니다.
- `saves` 는 줄어드는 글자 수입니다. 항상 로드되는 내용에서 줄면 `savesScope: "always"`, 파일을 열 때 로드되는 내용에서 줄면 `"conditional"` 로 적습니다. 적지 않으면 `kind` 로 짐작합니다.
- `false-positive` 가 나오면 원인(어느 판별이 틀렸는지)을 `evidence` 에 적습니다. 원본을 옮겨 둔 패키지처럼 일부러 규약을 걸지 않는 곳이 `gap:` · `no-glossary` 에 반복해 나오면 `.claude/ctxscope.json` 의 `ignore` 에 그 경로를 더하자고 제안합니다.

### 쓰는 법

보고서의 「할 일」 표는 제목과 근거의 첫 문장만 한 줄로 보여 줍니다. 그 한 줄만 읽고 무엇을 할지 알 수 있게 씁니다.

- `title` 은 40자 안쪽으로, 할 일이 드러나게 동사로 끝냅니다. 「~가 겹칩니다」보다 「~를 한 곳으로 모읍니다」가 낫습니다.
- `title` 에는 사람이 부르는 이름(「admin 화면 지시문」, 「database 규칙」)을 쓰고 경로는 `action` 에만 씁니다.
- `evidence` 는 두 문장 안쪽입니다. 첫 문장에 잰 값(몇 자 · 몇 개 · 몇 번)을, 둘째 문장에 고치면 무엇이 달라지는지를 적습니다.
- `action` 은 동사로 끝나는 한 줄짜리 목록입니다. ①②③ 같은 번호를 붙이지 않고 문장마다 「 · 」로 잇습니다.
