# 개선 제안

스크립트는 잴 수 있는 것만 제안합니다. 글을 읽어야 판단되는 것은 이 스킬이 맡습니다. 판단한 것은 `advice.json` 에 적어 보고서에 함께 싣습니다.

## 차례

1. 지도와 보고서가 없으면 `map` · `report` 스킬로 만듭니다.
2. 스크립트가 낸 제안을 읽고, 아래 「평가하는 법」으로 하나씩 확인합니다.
3. 판단을 자료 폴더의 `advice.json` 에 적고 보고서를 다시 조립합니다.
4. 사용자에게는 먼저 할 것 세 가지와 보고서 경로를 말합니다. ⚠ 지시문을 직접 고치지 않습니다. 고치는 일은 사용자가 고른 뒤입니다.

## 평가하는 법

**늘 실리는 것(수준 1)은 자격을 따집니다.** 루트 CLAUDE.md 의 절과 스킬 설명 하나하나에 세 가지를 묻습니다.

| 물음 | 내리는 쪽 | 두는 쪽 |
|---|---|---|
| 범위: 어떤 작업에 필요한가 | 특정 폴더 · 파일 종류에서만 필요하다 | 어느 작업에서나 필요하다 |
| 빼 보기: 빼면 행동이 달라지나 | 시나리오 결과가 같다 | 결과가 나빠진다 |
| 값: 어길 때 무엇을 잃나 | 고치면 되는 것 | 되돌리기 어려운 것(보안 · 스키마 · 밖으로 나가는 것) |

내릴 곳은 좁은 순서로 고릅니다. 경로가 정해지면 `paths` 가 있는 규칙으로, 폴더가 정해지면 그 폴더의 CLAUDE.md 로, 절차라면 스킬로 내리고 루트에는 가리키는 한 줄만 남깁니다.

**모델이 골라야 실리는 것(수준 4 · 5)은 뜻을 정합니다.** 꼭 읽혀야 하는 것이면 「필수」, 아니면 「선택」입니다. 필수인데 수준 5 에 있으면 올립니다. 올리는 길은 셋입니다: 그 작업의 경로 규칙에서 이름을 부르거나(4), 내용을 경로 규칙으로 옮기거나(2), 훅으로 강제합니다(3). 선택인데 한 번도 불리지 않은 스킬은 설명만 자리를 차지하므로 목록에서 빼거나 지웁니다.

**잘리는 글과 끊긴 길은 그대로 고칩니다.** 잰 사실이라 따로 확인할 것이 없습니다.

## advice.json

```json
{
    "suggestions": [
        {
            "id": "demote:커밋", "kind": "demote", "severity": "medium", "confidence": "heuristic",
            "title": "루트의 「커밋」 절은 커밋할 때만 필요합니다",
            "evidence": "커밋 메시지의 형식만 다루고, 코드를 읽거나 고치는 동안에는 쓰이지 않습니다.",
            "action": "절을 스킬로 옮기고 루트에는 「커밋 전에 그 스킬을 읽는다」 한 줄만 남깁니다.",
            "targets": ["CLAUDE.md"], "saves": 487
        }
    ]
}
```

- `id` 가 스크립트의 제안과 같으면 그 제안을 덮습니다. 시나리오로 확인했으면 `confidence` 를 `measured` 로 바꾸고 `evidence` 에 「5번 가운데 몇 번」을 적습니다.
- `kind` 는 `demote`(늘 실리는 곳에서 빼기) · `truncation` · `dead-ref` · `coverage` · `trace` 가운데 하나입니다.
- `confidence` 를 속이지 않습니다. 글만 읽고 내린 판단은 `heuristic` 입니다.
