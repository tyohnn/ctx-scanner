# 내용을 둘 위치 고르기

지시문 한 덩어리(섹션 하나, 규칙 하나)를 어디에 둘지 정할 때 읽습니다. 저장소 전체를 다시 배치할 때는 `layout.md` 를 함께 읽습니다. 위치마다 로드되는 시점과 로드 단위가 다릅니다.

## 위치마다 다른 점

| 위치 | 로드되는 시점 | 로드 단위 | 비용 |
|---|---|---|---|
| 루트 `CLAUDE.md` | 세션 시작 | 파일 전체 | 모든 요청의 앞쪽에 들어갑니다. 압축 뒤에도 다시 로드됩니다 |
| `paths` 없는 규칙 | 세션 시작 | 파일 전체 | 루트와 같습니다. 파일만 나뉩니다 |
| 폴더 `CLAUDE.md` | 그 폴더의 파일을 Read · Edit · Write 로 처음 열 때 | **폴더 전체에 파일 전체** | 어느 파일을 열어도 전부 로드됩니다. 20만 세션은 40,000자에서 잘립니다 |
| `paths` 있는 규칙 | 경로에 맞는 파일을 Read · Edit · Write 로 처음 열 때 | **경로 패턴에 파일 전체** | 맞는 파일을 열 때만 로드됩니다. 한 파일에 여러 규칙이 겹치면 모두 로드됩니다 |
| 스킬 | 설명은 세션 시작, 본문은 모델이 호출할 때 | 설명 한 칸 + 본문 | 설명은 항상 로드되고 본문이 읽힐지는 모델이 정합니다 |
| 훅 · 검사 스크립트 | 이벤트가 발생하면 자동으로 실행 | 스크립트가 내는 내용 | 모델이 고르지 않아도 걸립니다 |
| `docs/` | 모델이 찾아 읽을 때 | 읽은 만큼 | 참조하는 곳이 없으면 읽히지 않습니다 |

폴더 지시문과 경로 규칙은 둘 다 필요할 때 대화의 뒤에 붙습니다. 앞쪽에 캐시된 부분을 바꾸지 않으므로, 항상 로드되는 곳에서 이 둘로 내용을 옮기면 모든 요청의 앞쪽이 줄어듭니다.

⚠ 둘 다 Bash 의 `cat` · `grep` 으로 파일을 읽으면 로드되지 않습니다. 위치를 옮겨도 이 점은 같습니다.

## 고르는 차례

위에서부터 물어 처음 「예」가 나온 위치에 둡니다.

1. **자동으로 검사할 수 있나.** 예이면 검사 스크립트나 훅입니다. 문장으로만 두면 모델이 따라야만 지켜집니다.
2. **여러 단계의 절차이고 그 일을 할 때만 필요한가.** 예이면 스킬입니다. 꼭 읽혀야 하면 그 일이 벌어지는 경로의 규칙에서 스킬의 이름을 언급합니다.
3. **왜 그렇게 정했는지의 설명이나 찾아볼 자료인가.** 예이면 `docs/` 이고, 지시문에는 참조하는 한 줄만 둡니다.
4. **어느 작업에서나 걸리나.** 예이면 루트 CLAUDE.md 입니다. `paths` 없는 규칙은 루트가 길어져 주제별로 파일을 나누고 싶을 때만 씁니다. 비용은 같습니다.
5. **한 폴더의 어느 파일을 열어도 필요한가.** 예이면 그 폴더의 CLAUDE.md 입니다. 그 폴더가 무엇이고 어떻게 짜였는지, 그 폴더에서만 쓰는 명령과 용어가 여기에 맞습니다.
6. 나머지는 **`paths` 있는 규칙**입니다. 아래 가운데 하나에 해당합니다.
   - 파일 종류에 걸립니다(`**/*.test.ts`, `supabase/migrations/**`).
   - 여러 폴더에 걸칩니다(앱 셋의 서버 액션).
   - 폴더의 일부에만 걸립니다(`apps/admin/src/lib/**`).

## 둘 사이에서 망설일 때

| 신호 | 폴더 CLAUDE.md | 경로 규칙 |
|---|---|---|
| 그 내용이 필요한 파일이 폴더의 몇 %인가 | 대부분 | 일부(맵의 「범위가 좁은 섹션」) |
| 같은 내용이 다른 폴더에도 있나 | 없다 | 있다(맵의 「거의 같은 내용」 · 「따로 적고 있습니다」) |
| 폴더 지시문이 상한에 가까운가 | 여유 있다 | 85%를 넘었다. 범위가 좁은 섹션부터 옮긴다 |
| 폴더가 옮겨질 수 있나 | 내용이 폴더를 따라 움직인다 | 경로가 끊긴다. 옮긴 뒤 맵에서 「맞는 파일이 없습니다」를 확인한다 |
| 사람이 어디서 찾나 | 코드 옆 | `.claude/rules/` 한곳 |

⚠ 규칙을 잘게 나누는 데에도 비용이 듭니다. 한 파일에 규칙이 네댓 개 겹치면 폴더 지시문 하나보다 많이 로드될 수 있고, 조건이 저장소의 절반을 넘으면 항상 로드되는 것과 다르지 않습니다. 맵의 「파일」 화면에서 옮긴 뒤의 합을 확인합니다.

## 옮긴 것을 확인하는 법

1. 옮긴 뒤 `map` 스킬로 맵을 다시 만듭니다. 폴더 지시문의 크기가 줄고 새 규칙의 경로에 맞는 파일 수가 0이 아닌지 봅니다.
2. `test` 스킬로 시나리오 둘을 돌립니다. 그 경로의 파일을 고치는 요청에서 새 규칙이 로드되는지, 그 폴더의 다른 곳을 고치는 요청에서 로드되지 않는지입니다.
3. 통과하면 제안의 `confidence` 를 `measured` 로 고칩니다.
