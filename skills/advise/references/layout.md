# 겹치지 않고 빠짐없이 배치하기

저장소 전체의 지시문을 다시 배치할 때 읽습니다. 섹션 하나의 위치만 정할 때는 `placement.md` 로 충분합니다.

지시문끼리는 우선순위가 없습니다. 로드된 것은 모두 이어 붙고, 서로 어긋나면 어느 쪽을 따를지 정해져 있지 않습니다. 그래서
목표는 둘입니다. **같은 말은 한 곳에만 둡니다(겹침 없이).** **어느 파일을 건드리든 그 파일에 필요한 규약이 로드됩니다(빈칸 없이).**

## 파일 하나가 로드하는 것

파일 하나를 Read · Edit · Write 로 건드리면 세 축에서 로드가 일어나고, 그 뒤는 모델이 필요할 때만 읽습니다. 보고서의 「플로우」
화면이 영역과 위치마다 이 줄을 하나씩 보여 줍니다.

| 단계 | 축 | 묻는 것 | 로드되는 것 | 두는 내용 |
|---|---|---|---|---|
| 항상 | | | 루트 `CLAUDE.md`, 스킬 목록 | 모든 작업에 걸리는 것 |
| ② 자동 | 폴더 | 어느 앱 · 기능 폴더 아래인가 | 앱 `CLAUDE.md` + 기능 폴더 `CLAUDE.md` | 그 폴더에서만 맞는 사실과 함정 |
| ② 자동 | 계층 | 어느 계층 · 파일 종류인가 | 계층 규약 규칙 | 「어떻게 만드나」의 금지와 핵심 |
| ② 자동 | 도메인 | 어느 도메인의 코드인가 | 도메인 용어 규칙 | 「무엇이라 부르나」 |
| ③ 필요할 때만 | | 규칙의 마지막 줄이 가리키나 | 스킬 → 그 스킬이 가리키는 공식 스킬의 파일 | 절차와 예시 |

세 축은 서로 다른 것을 묻기 때문에 한 파일에 셋이 함께 로드되어도 내용이 겹치지 않습니다. 겹침은 한 축의 내용을 다른 축의
위치에 적을 때 생깁니다(앱 CLAUDE.md 에 여러 앱 공통인 서버 액션 규약을 적는 것, 루트에 한 도메인의 용어를 적는 것).

## 문장 하나의 위치 정하기

문장마다 위에서부터 물어 처음 「예」가 나온 위치에 둡니다.

| 물음 | 위치 |
|---|---|
| 자동으로 검사할 수 있나 | 검사 스크립트 · 훅. 검사가 생기면 문장은 지운다 |
| 왜 그렇게 정했는지의 배경인가 | `docs/decisions/` 같은 결정 기록 |
| 비즈니스 규칙이나 정책 자체인가 | `docs/`. 규칙에는 넣지 않는다 |
| 여러 단계의 절차나 예시인가 | 스킬 |
| 모든 작업에 걸리나 | 루트 `CLAUDE.md` |
| 도메인 용어인가(뜻 · 코드 이름 · 쓰지 않는 말) | `.claude/rules/glossary/<도메인>.md` |
| 계층이나 파일 종류에 걸리는 금지 · 규약이고 여러 앱에 공통인가 | `.claude/rules/<계층>.md` |
| 앱 하나 전체에 걸리나 | 그 앱의 `CLAUDE.md` |
| 기능 폴더 하나에만 걸리나 | 그 폴더의 `CLAUDE.md` |
| 환경 변수 표나 파일 목록인가 | `.env.example` 에 두거나 지운다. 코드가 답한다 |

## 규칙을 둘로 나누기

경로 규칙은 역할이 둘입니다. 맵은 규칙마다 `role` 을 붙이고(`layer` · `domain`, 어느 영역에도 몰려 있지 않으면 `common`)
플로우 화면에서 다른 칸에 놓습니다.

**계층 규약 규칙** `.claude/rules/<계층>.md`

- `paths` 는 계층 폴더나 파일 종류입니다. 앱 이름을 적지 않고 `apps/*/src/actions/**` 처럼 폴더 이름으로 적어야 새 앱에도 걸립니다.
- 내용은 그 계층을 만드는 금지와 핵심만, 1,500자 안팎입니다. 예: 「서버 액션은 관문을 지난 것만 내보낸다」.
- ⚠ 금지는 규칙에 남깁니다. 스킬로 내리면 모델이 스킬을 열지 않은 세션에서는 금지가 보이지 않습니다.
- 마지막 줄에 스킬로 넘기는 한 줄을 둡니다(아래 「규칙에서 스킬로 넘기기」).

```markdown
---
paths:
  - "apps/*/src/actions/**"
---
# 서버 액션

- 관문 `appAction` 을 지난 것만 내보낸다. 서버 액션은 공개 엔드포인트다.
- 판정은 도메인 패키지의 순수 함수에 두고 액션 안에 넣지 않는다.

새 액션을 만들거나 입력 모양을 바꿀 때는 `.claude/skills/server-action/SKILL.md` 를 연다.
```

**도메인 용어 규칙** `.claude/rules/glossary/<도메인>.md`

- `paths` 는 그 도메인의 코드가 있는 폴더 전부입니다. 도메인 패키지, 앱 안의 그 도메인 폴더, 어댑터의 그 도메인 폴더를 함께 적습니다.
- 내용은 용어 표 하나입니다. 칸은 `용어 · 뜻 · 코드 이름 · 쓰지 않는 말` 넷입니다. 비즈니스 규칙과 절차는 넣지 않습니다.
- 용어 하나는 한 도메인만 정의합니다. 다른 도메인이 그 말을 쓰면 다시 정의하지 않고, 소유한 쪽 규칙의 `paths` 에 그 폴더를 더합니다.
- 루트나 앱 CLAUDE.md 에 있던 용어 표는 여기로 옮기고 원래 위치에는 남기지 않습니다.

```markdown
---
paths:
  - "packages/sales/**"
  - "apps/admin/src/{actions,usecases}/deal*"
---
# 영업 용어

| 용어 | 뜻 | 코드 이름 | 쓰지 않는 말 |
|---|---|---|---|
| 딜 | 계약이 되기 전의 파이프라인 한 건 | `sales.deal` | 기회, 리드 |
```

## 규칙에서 스킬로 넘기기

규칙은 자동으로 로드되므로 짧게 두고, 길어지는 절차와 예시는 스킬에 둡니다. 규칙이 그 스킬의 입구입니다.

1. **규칙의 마지막 줄에 조건과 경로를 적습니다.** 「새 액션을 만들거나 입력 모양을 바꿀 때는 `.claude/skills/server-action/SKILL.md` 를 연다」.
   조건이 없으면 모델이 매번 열거나 한 번도 열지 않습니다. 경로를 적어야 목록에서 뺀 스킬도 읽을 수 있습니다.
2. **스킬에는 이 저장소만의 차이를 적습니다.** 받아 둔 공식 스킬이 이미 다루는 내용은 다시 쓰지 않고 그 파일의 경로를 가리킵니다
   (`.claude/skills/<공식 스킬>/rules/<파일>.md`). ⚠ 공식 스킬의 파일은 고치지 않습니다. 잠금 파일이 해시를 고정하고 있고 다음에 받을 때 덮어써집니다.
3. **규칙이 가리키는 스킬은 목록에서 설명을 뺍니다.** `.claude/settings.json` 의 `skillOverrides` 에 적습니다.

   | 값 | 목록에 남는 것 | 맞는 스킬 |
   |---|---|---|
   | `on`(기본) | 이름과 설명 | 어느 작업에서나 쓰는 스킬 |
   | `name-only` | 이름 | 규칙이 이름으로 가리키는 스킬 |
   | `user-invocable-only` | 없음 | 규칙이 경로로 가리키거나 사람만 호출하는 스킬 |
   | `off` | 없음 | 쓰지 않는 스킬 |

맵은 「규칙 → 스킬」을 점선으로 그리고, 플로우 화면의 ③ 칸에 「스킬 → 그 스킬이 가리키는 스킬」까지 보여 줍니다. 가리키는 경로가
없으면 「깨진 참조」로, 목록에서 뺀 스킬을 이름으로만 가리키면 `hidden-skill:` 로 냅니다.

깨진 참조는 문서의 폴더를 기준으로 상대 경로(`../CLAUDE.md`)를 접어서 찾습니다. 같은 줄에 커밋 해시가 있으면 지난 커밋의 경로이고,
첫 폴더가 저장소 어디에도 없으면(`자료/` · `.pr-check/` · `.vercel/`) 쓰는 사람이 만드는 작업 폴더나 예시라서 깨진 참조로 세지 않고
지도에 `outside` 로만 남깁니다.

## CLAUDE.md 세 층

| 층 | 두는 것 | 두지 않는 것 |
|---|---|---|
| 루트 | 모든 작업에 걸리는 것. 「이 문장은 어디로 가나」 표 | 한 도메인의 용어, 한 계층의 규약 |
| 앱 `CLAUDE.md` | 색인. 이 앱이 무엇인지, 어느 하위 폴더에 어떤 `CLAUDE.md` 가 있는지 | 기능별 설명, 여러 앱에 공통인 규약 |
| 기능 폴더 `CLAUDE.md` | 그 폴더에서만 맞는 사실과 함정(크론 하나, 웹훅 창구 하나, MCP 엔드포인트) | 다른 폴더에도 맞는 규약 |

앱 CLAUDE.md 는 그 앱의 어느 파일을 열어도 전부 로드됩니다. 기능 하나의 긴 설명을 여기에 두면 다른 기능을 고칠 때도 함께
로드되고 잘리는 길이(20만 세션 40,000자)에 가까워집니다. 기능 폴더로 내리고 앱에는 한 줄만 남깁니다.

## 맵이 내는 겹침 · 빈칸 제안

`kind` 가 `mece` 인 제안입니다. 보고서 「제안」의 「겹침과 빈칸」에 모입니다.

| 제안 id | 측정한 것 | 읽고 정할 것 |
|---|---|---|
| `term-dup:` | 같은 용어가 두 곳의 용어 표에 있다 | 어느 도메인이 그 말을 소유하나 |
| `terms-home:` | 용어 표가 루트나 폴더 지시문에 있다 | 용어를 도메인별로 나누고 규칙의 `paths` 를 정한다 |
| `rule-overlap:` | 두 규칙이 거의 같은 파일에 걸린다 | 합칠지, 경로를 좁혀 나눌지 |
| `defer:` | 규칙이 자세한 내용을 폴더 지시문에 넘기는데 그 폴더 지시문은 일부 파일에서만 로드된다 | 공통 규약이면 규칙으로 옮기고, 그 폴더만의 것이면 경로를 좁힌다 |
| `gap:` | 같은 영역인데 일부 위치에는 계층 규칙이 걸리지 않는다 | 일부러 다르게 둔 위치인지(옮겨 온 코드, 손대지 않는 패키지) |
| `no-layer:` | 영역에 계층 규칙이 없다 | 그 영역에 여러 곳 공통인 규약이 실제로 있는지 |
| `no-glossary` | 도메인 용어 규칙이 걸리지 않는 패키지가 있다 | 고유한 용어가 있는 패키지인지 |
| `long-rule:` | 용어 규칙이 아닌 규칙이 3,000자를 넘는다 | 금지와 핵심만 남기고 무엇을 스킬로 넘길지 |
| `pointed-skills` | 규칙이 가리키는 스킬의 설명이 항상 로드된다 | `name-only` 와 `user-invocable-only` 가운데 무엇으로 할지 |
| `unindexed:` | 하위 폴더 지시문이 상위 지시문에 적혀 있지 않다(`{a,b}` 로 묶어 적은 것은 펼쳐서 본다) | 색인에 넣을 한 줄 |

같은 내용이 여러 곳에 있는 것은 `placement.md` 의 `dup:` · `same-topic:` 이 냅니다. 함께 봅니다.

## 영역 정하기

플로우의 줄은 「영역 × 위치」입니다. 영역은 경로 패턴으로 정하고 위에서부터 처음 맞는 것을 씁니다. 기본값은 테스트 · DB 를 먼저 보고
(`actions/x.test.ts` 는 서버 액션이 아니라 테스트입니다) 그다음 서버 액션 · 유스케이스 · 크론 · 웹훅 · MCP · API 라우트 · 화면 · UI 컴포넌트 ·
포트 · 어댑터 · 패키지 코드 · 앱의 그 밖의 코드 순서입니다. 보고서는 테스트 · DB 를 맨 끝에 보여 줍니다. 저장소의 폴더 이름이 다르면
`.claude/ctxscope.json` 의 `areas` 에 적습니다. 기본 영역에 덧씌우므로 바꿀 영역만 적습니다. id 가 같으면 그 영역의 `label` · `paths` 가
바뀌고, 새 id 는 「패키지 코드」 앞에 들어갑니다. 기본값을 버리고 처음부터 적으려면 `"replaceAreas": true` 를 줍니다.

규칙이 어느 영역의 규약인지는 그 규칙에 맞는 코드 파일이 어느 영역에 4분의 1 넘게 몰려 있는지로 봅니다. 테스트 파일은 규칙에 맞는
파일의 절반을 넘을 때만 셉니다. 코드 파일의 절반 넘게 걸리는 규칙(파일 크기 제한)은 영역을 가리지 않는 공통 규칙이고, 「패키지 코드」에만
몰린 규칙(도메인 패키지 규약)은 그 위치의 모든 영역에서 계층 칸에 들어갑니다.

원본을 그대로 옮겨 둔 패키지처럼 일부러 규약을 걸지 않는 곳은 `ignore` 에 적어 플로우와 빈칸 검사에서 뺍니다. 저장소 맨 위의 점으로
시작하는 폴더는 기본으로 뺍니다.

```json
{
    "areas": [
        { "id": "api", "paths": ["apps/*/src/app/api/**/route.ts"] },
        { "id": "domain", "label": "도메인 패키지", "paths": ["packages/{sales,legal,access}/src/**"] }
    ],
    "ignore": ["packages/vella-ui/**"]
}
```

## 전체를 다시 배치하는 차례

1. 맵을 만들고 「플로우」에서 영역마다 한 줄씩 읽습니다. 계층 칸과 도메인 칸이 비어 있는 줄, 폴더 칸의 글자 수가 유난히 큰 줄을 적어 둡니다.
2. 큰 폴더 지시문을 섹션 단위로 위의 「문장 하나의 위치 정하기」에 넣습니다. 계층 규약 · 도메인 용어 · 기능 폴더 · 문서 · 스킬로 나뉩니다.
3. 계층 규칙과 도메인 용어 규칙의 목록과 `paths` 를 먼저 표로 정합니다. 이때 `rule-overlap:` 이 나오지 않게 경로를 맞춥니다.
4. 규칙마다 넘길 스킬을 정합니다. 공식 스킬이 있으면 차이만 쓰는 스킬을 만들고, `skillOverrides` 값을 정합니다.
5. `advice.json` 에 옮길 것을 제안으로 적습니다. 제안마다 「지금 이 파일을 고치면 N자 → 옮긴 뒤 M자」를 플로우의 자동 로드 값으로 적습니다.
6. 사용자가 고른 것을 옮긴 뒤 맵을 다시 만들어 겹침 · 빈칸 제안이 줄었는지 보고, `test` 스킬로 규칙이 로드되고 스킬이 열리는지 시나리오로 확인합니다.

⚠ 규칙을 잘게 나누는 것이 목표가 아닙니다. 한 파일에 규칙이 대여섯 개 겹치면 폴더 지시문 하나보다 많이 로드됩니다. 플로우의
「자동 로드」 값이 옮기기 전보다 줄었는지로 판단합니다.
